# 🧐 A cerca del proyecto - GuitarLA
Desarrollo de una WebApp para usuarios que desen comprar guitarras de todo tipo de marcas. El comportamiendo será similar al de un pequeño eCommerce.

## 📰 Descripción
Descripción a cerca de la infraestructura de la App.
  * Header
      - NavBar
      - Carro de comprar actualizable con los precios de los productos a comprar.
      - Wellcome side.
  * Body
      - Los productos a comprar
      - Precios
      - Imágenes
  * Footer
      - Información adicional para el cliente
      - Redes sociales
      - Copyright

## 🪧 Descargar e instalar proyecto
Pasos a seguir para poder descargar e inicializar nuestro proyecto en local.

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/prism-themes@1.9.0/themes/prism-dracula.min.css">
<p align="left">1. Acceder al repo de GitHub.</p>
<p align="left">2. Copiar la url del proyecto con los protocolos https o ssh.</p>
<p align="left">3. Abrir una nueva terminal y posicionarnos sobre el directorio donde almacenaremos el repo del proyecto.</p>
<p align="left">4. Descargar nuestro repo en local con Git.</p>
<pre style="border-radius: 20px">
  <code>
     git clone https://proyect_url o git clone ssh://proyect_url
  </code>
</pre>
<p align="left">5. Proteger tu proyecto contra paquetes maliciosos. <b>No es obligatorio, pero si recomiendado.</b></p>
<p>El proceso consiste en ejecutar el siguiente comando en la terminal asociado al empaquetador de dependencias que se este usando. Esto permite ignorar la ejecucicón de los scripts por defecto, que es una de las mejores soluciones en seguridad contra la prevención de auto-ejecución de paquetes. 

Ya que algunos pueden ser de indole maliciosa y no deseados. Esto suele asociarse a los empaquetadores de dependencias como NPM o PNPM. Pero revisa si otros empaquetadores como Yarn o Bun también necesitan de habilitar esta funcionalidad o ya la incorporan activa por defecto.

Este comando lo has de ejecutar como recomendación, en caso de querer realizar un deploy de tu proyecto más seguro a **PRO** a través de un hosting. Si siempre se va a mantener el proyecto almacenado de forma local puedes ignorar este paso.</p>
<pre style="border-radius: 20px">
  <code>
     pnpm install --ignore-scripts package-name
     npm install --ignore-scripts package-name
  </code>
</pre>
<p align="left">6. Instalar las dependencias del proyecto con tu empaquetador de dependencias favorito.</p>
<pre style="border-radius: 20px">
  <code>
     pnpm install o pnpm i
  </code>
</pre>
<pre style="border-radius: 20px">
  <code>
     npm install o npm i
  </code>
</pre>
<pre style="border-radius: 20px">
  <code>
     yarn install o yarn i
  </code>
</pre>
<pre style="border-radius: 20px">
  <code>
     bun install o bun i
  </code>
</pre>
<p align="left">7. Lavantar proyecto en local.</p>
<p><b>Nota: </b>Sustituye PNPM por tu empetador de dependencias favorito o usa NodeJS a partir de la versión 22 en su lugar como ejecutor de scripts.</p>
<pre style="border-radius: 20px">
  <code>
     pnpm run dev o node --run dev
  </code>
</pre>
